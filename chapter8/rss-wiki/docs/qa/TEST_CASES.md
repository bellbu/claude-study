# RSS Wiki — 테스트 케이스

- 기준 문서: docs/PRD.md (v0.1)
- 작성일: 2026-10-20
- 우선순위: P1(핵심 흐름·데이터 손실 위험) / P2(주요 기능) / P3(보조 기능)
- 수행 방식
  - **E2E-자동**: `tests/e2e/test_e2e_flow.py` — 실제 서버 프로세스(uvicorn) + 로컬 픽스처 서버(RSS·원문·Mock Claude API)에 HTTP로 접근
  - **E2E-브라우저**: Playwright로 실제 브라우저에서 화면 조작
  - **단위**: `tests/` 아래 단위·통합 테스트

## 테스트 환경

| 구성 | 내용 |
|---|---|
| 앱 | `python -m rss_wiki serve`, 임시 데이터 폴더, `127.0.0.1` 임의 포트 |
| 픽스처 서버 | `tests/e2e/fixture_server.py` — RSS 피드, 원문 HTML, 사이트(피드 자동 탐지), 실패 피드(503/404/429), Mock Claude `/v1/messages` |
| LLM | `ANTHROPIC_BASE_URL`을 픽스처 서버로 지정. 실제 anthropic SDK가 HTTP 요청을 보내고, Mock이 요청 스키마에 맞는 결정적 JSON을 돌려준다 |
| 한계 | 실제 Claude 모델의 요약·재작성 품질과 실제 비용은 검증 범위 밖 (API 키 없음) |
