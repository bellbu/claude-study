# rss-wiki PRD

- 작성일: 2026-10-29
- 상태: 초안 v2 (2026-11-02: 웹 UI, 디자인 품질, 요약 병렬 실행 추가)

## 1. 개요

RSS/Atom 피드에서 글을 수집하고, LLM(Claude)으로 글마다 한국어 요약을 만든 뒤,
요약을 주제별 위키 문서로 정리하는 **개인용 로컬 도구**입니다. CLI와 로컬 웹 UI를 제공합니다.

### 목표
- 구독한 피드의 새 글을 명령 하나로 수집하고 요약합니다.
- 글별 요약을 Markdown 파일로 남기고, 주제(태그)별 위키 페이지에 링크로 쌓습니다.
- 피드 등록, 수집 실행, 수집된 글 보기를 웹에서 할 수 있습니다.
- 실패한 항목이 전체 실행을 멈추지 않으며, 다음 실행 때 다시 시도합니다.

### 비목표
- 다중 사용자, 인증, 원격 서버 배포
- TUI
- 도구 내장 스케줄러 (주기 실행은 OS 작업 스케줄러/cron에 맡김)
- 피드 리더 기능 (읽음 표시, 즐겨찾기 등)

## 2. 사용 범위
- 사용자: 1인 (개발자 본인)
- 환경: 로컬 PC (Windows 우선, macOS/Linux에서도 동작)
- 런타임: Python 3.14 이상, uv로 패키지 관리, 엔트리포인트 `rss-wiki`

## 3. UI: 서브커맨드 기반 CLI

| 명령 | 설명 |
|---|---|
| `rss-wiki init` | 데이터 디렉터리, SQLite DB, 기본 설정 파일 생성 |
| `rss-wiki feed add <url> [--name NAME]` | 피드 등록 (등록 시 URL 유효성 확인) |
| `rss-wiki feed list` | 등록된 피드 목록과 마지막 수집 시각·상태 출력 |
| `rss-wiki feed remove <id\|url>` | 피드 삭제 (기존 글/요약은 유지) |
| `rss-wiki fetch [--feed ID]` | 피드에서 새 글 수집 후 DB에 저장 |
| `rss-wiki summarize [--limit N] [--retry-failed]` | 요약되지 않은 글을 LLM으로 요약해 Markdown으로 저장 |
| `rss-wiki build` | 주제별 위키 페이지와 인덱스 재생성 |
| `rss-wiki run` | `fetch` → `summarize` → `build`를 차례로 실행 (스케줄러용) |
| `rss-wiki status` | 수집/요약 대기·실패 건수 요약 |
| `rss-wiki serve [--port 8000]` | 로컬 웹 UI 실행 (5장) |

공통 규칙
- 종료 코드: 전부 성공하면 0, 일부 항목만 실패하면 1, 설정 오류나 치명적 오류면 2
- `--verbose` / `--quiet` 로그 수준 옵션
- 출력은 사람이 읽는 텍스트만 제공하며 기계 판독용 `--json`은 제공하지 않습니다 (자체 결정: 합의)

## 4. 핵심 기능

### 4.1 피드 관리
- RSS 2.0과 Atom을 지원합니다.
- 피드 URL은 중복 등록할 수 없습니다.

### 4.2 수집 (fetch)
- 글은 `guid`(없으면 링크 URL)로 식별해 중복 저장을 막습니다.
- 본문 수집 정책: **RSS 본문을 우선 사용하고, 짧으면 원문을 추출합니다.**
  - RSS의 `content`/`description`을 텍스트로 바꾼 길이가 기준값(기본 500자)보다 짧으면
    원문 페이지를 가져와 본문을 추출합니다.
  - 원문 추출에 실패하면 RSS 본문으로 요약하고, 이 사실을 기록합니다.
- 조건부 요청(ETag / Last-Modified)으로 불필요한 다운로드를 줄입니다.
- HTTP 타임아웃은 기본 15초입니다.

### 4.3 요약 (summarize)
- LLM: **Claude API가 기본입니다** (Anthropic Python SDK, 기본 모델 `claude-haiku-5-5`, 설정으로 변경 가능).
- LLM 호출은 공급자 인터페이스(예: `Summarizer` 프로토콜) 뒤로 분리해 이후 다른 공급자를 붙일 수 있게 합니다.
- 원문 언어와 관계없이 요약은 **항상 한국어**입니다.
- 출력 형식은 구조화된 응답(JSON 스키마)으로 받아 검증합니다.
  - `tldr`: 1~2문장 요약
  - `key_points`: 핵심 포인트 3~5개
  - `tags`: 주제 태그 1~5개 (소문자, 기존 태그 목록을 프롬프트로 함께 넘겨 재사용 유도)
- 입력 본문은 최대 길이(기본 약 20,000자)를 넘으면 잘라서 보냅니다.
- **병렬 실행**: 글별 LLM 호출을 병렬로 실행해 속도를 높입니다. 동시 실행 수는 설정 `summarize.concurrency`(기본 4)로 정합니다. DB 저장은 한 번에 하나씩 하고, 한 글의 실패는 다른 글에 영향을 주지 않습니다.

### 4.4 정리 (build)
- **글별 요약 Markdown**: `wiki/articles/YYYY/MM/<slug>.md`
  - front matter: 제목, 원문 URL, 피드명, 발행일, 요약일, 모델, 태그
  - 본문: TL;DR, 핵심 포인트, 원문 링크
- **주제별 위키 페이지**: `wiki/topics/<tag>.md`
  - 해당 태그가 붙은 글 요약 링크를 최신순으로 나열 (TL;DR 한 줄 포함)
- **인덱스**: `wiki/index.md`. 태그 목록(글 수 포함)과 최근 요약 글 목록
- `build`는 DB를 기준으로 위키 페이지를 결정적으로 재생성합니다 (멱등).

## 5. 웹 UI

`rss-wiki serve`로 띄우는 로컬 웹 화면입니다 (`127.0.0.1` 전용). CLI와 같은 기능 코드를 호출합니다.

- **피드 관리**: 피드 목록, 등록, 삭제
- **수집하기**: 버튼으로 `run`(fetch → summarize → build) 실행, 진행 상황 표시
- **글 보기**: 수집된 글 목록과 상세(TL;DR, 핵심 포인트, 태그, 원문 링크), 태그별 보기

### 디자인 품질
- 색상·글꼴·간격을 디자인 토큰(CSS 변수)으로 통일합니다.
- 한국어 가독성을 우선한 타이포그래피, 반응형 레이아웃, 다크 모드를 지원합니다.
- 빈 상태·로딩·오류 화면도 디자인합니다.
- 화면을 바꿀 때마다 스크린샷으로 확인합니다.

## 6. 데이터 저장

- 메타데이터: **SQLite** (`data/rss-wiki.db`)
- 결과물: **Markdown 파일** (`wiki/`)
- 기본 데이터 디렉터리는 현재 작업 디렉터리이며, 설정이나 `--data-dir`로 바꿀 수 있습니다.

### 주요 테이블 (개략)
| 테이블 | 주요 컬럼 |
|---|---|
| `feeds` | id, url(unique), name, etag, last_modified, last_fetched_at, last_status, error_count |
| `articles` | id, feed_id, guid(unique per feed), url, title, published_at, content, content_source(rss/extracted), fetched_at |
| `summaries` | article_id, status(pending/done/failed), tldr, key_points(JSON), model, attempts, last_error, summarized_at |
| `tags` / `article_tags` | 태그와 글의 다대다 관계 |

### 설정
- 설정 파일: `rss-wiki.toml` (모델명, 본문 길이 기준, 타임아웃, 재시도 횟수, 경로, 요약 동시 실행 수)
- API 키는 환경 변수 `ANTHROPIC_API_KEY`로만 받고, 설정 파일이나 DB에는 저장하지 않습니다.

## 7. 외부 연동

| 대상 | 용도 | 비고 |
|---|---|---|
| RSS/Atom 피드 서버 | 글 수집 | HTTP GET, User-Agent 명시 |
| 원문 웹페이지 | 본문 추출 | RSS 본문이 짧을 때만 |
| Anthropic Claude API | 요약 생성 | `ANTHROPIC_API_KEY` 필요 |

## 8. 실패 정책

- **항목 단위 격리**: 피드 하나나 글 하나가 실패해도 나머지 처리는 계속합니다.
- **기록**: 실패 원인을 DB(`last_error`, `error_count`/`attempts`)와 로그에 남깁니다.
- **재시도**
  - 일시적 오류(네트워크, 5xx, 429, LLM 과부하)는 한 번 실행하는 동안 지수 백오프로 최대 3회 재시도합니다.
  - 그래도 실패하면 다음 실행 때 다시 시도합니다.
  - 누적 실패가 기준(기본 5회)을 넘으면 `failed` 상태로 고정하고 자동 재시도에서 뺍니다. `--retry-failed`로 수동 재시도할 수 있습니다.
- **검증 실패**: LLM 응답이 스키마에 맞지 않으면 실패 1회로 셉니다.
- **치명적 오류**: API 키가 없거나, 설정 오류이거나, DB를 열 수 없으면 즉시 종료합니다 (종료 코드 2).
- **멱등성**: 같은 명령을 다시 실행해도 중복 데이터가 생기지 않습니다.

## 9. 비기능 요구사항
- 테스트: 피드 파싱, 본문 정책, 실패 정책, 위키 생성은 네트워크/LLM 없이 테스트할 수 있어야 합니다 (HTTP·LLM 계층 대체 가능).
- 로깅: 표준 `logging`을 쓰고, 기본 INFO 수준으로 콘솔에 출력합니다.
- 인코딩: 모든 파일은 UTF-8입니다 (Windows 콘솔 포함).
